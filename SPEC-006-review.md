## Findings
1. **Slider value trap (fixed).** In a real browser, once a user drags the slider, writing the `value` *attribute* no longer moves the thumb, so a candidate that repaints with `setAttribute("value")` passes on first load and silently fails after a scrub. The dom-harness models the same split (`scrub()` sets the property; `snapshot()` reads `.value`), so R4/R8 catch it. A CONTEXT row now says it outright: set the `value` property on every paint.
2. **Safety rubric contradicted itself (fixed).** The `safety` grading text asked the judge to inject a `javascript:` URL into `links[]`, then said a correct page would draw it. That invites a judge to penalize correct behavior. It now injects the hostile URL into fields Replay must never turn into an `href` (`cand`, run `id`, run `agentId`), puts markup in every text field (entry title, link label, run label, idea), and keeps the 2,000-character no-space title for W7.
3. **R14 used the word "lane" (fixed).** That is angle vocabulary (Broadcast booth). It now says "the `Runs so far` item for c2".
4. **Live journey ordering (fixed).** `dd record … lesson_recorded` appends a 21st event to `p-20261017-94` in `$DATA`. Any probe run after it would see `Event N of 21`, and a retry without re-seeding would prove nothing. VERIFY 6 now says: run Live last; if it misses, run `seed-replay` again and retry once with `--wait 8000`.
5. **Comment trap on the R16 grep (fixed).** `history.` and `location.hash =` are banned in `replay.js`, comments included (same as W11's rule). The spec now says so, so a comment like `// no history. writes` does not fail a good candidate by surprise.
6. **Oracle button names (fixed in the oracle, not the spec).** `replay-check.mjs` R4 compared button *text*; an icon button with `aria-label="Play"` would have failed the oracle while passing the spec. It now uses the harness's `accessibleName()`. Ref still 192/192.
7. **Probe false pass at START (already mitigated).** `cdp-shot.mjs` at START returns `"ok":true` on the replay hash, because it falls back to the Big Board. The journey gate and R19 therefore also require `chips` to hold exactly one chip with the frame's status (`judging` at `?at=11`), plus the committed screenshot. At START the Big Board shows many chips, so the gate fails as it should.
8. **W19 lesson from Pick 4 (already applied).** The graft added `docs/SPEC-005…` and `test/phone.pooled.test.ts` that no touch-map row named, and the physical returned NOT_VERIFIED on the touch map alone. SPEC 006 pre-declares a grafter-only row: `docs/SPEC-006-replay.md`, `test/replay.pooled.test.ts` and replacement `docs/screens/p5-replay/*.png`. VERIFY 9 accepts them.
9. **1280 target-size lesson (already applied).** Pick 4 met 44×44 only on phones. R19 requires every Replay control and link to be ≥44×44 at every width, 1280 included. Play-by-play links inside `.dd-event` are the only exemption, matching `probe.js`. The 11 pre-existing 1280 W8 problems on the Big Board and pick page are out of scope. R19 checks only that none of them names `Replay`, which holds in the ref build (same 11 as START).
10. **Screenshots retrievable (already applied).** All ten PNGs are committed under `docs/screens/p5-replay/` and listed in the `dd-report`. Artifact links alone failed after Pick 4.
11. **Angles are distinct (checked).** c1 starts from the frame table and minimal hunks; c2 from the demo-video look (scoreboard, lower third, field at 1280, thumb bar); c3 from story navigation (stage chapters, VoiceOver order). All three must meet the same binding DOM, so the pooled tests stay comparable. Leak checks: angle words do not appear in the candidate or judge copies (`chapter`, `booth`, `scoreboard`, `lane`, `engine` grep clean). c3's extra controls are fenced: outside `Replay controls`, ≥44, never a `.chip`.
12. **Timing journeys are real-browser only (accepted).** Play (`--wait 4500` → a frame after `Event 1`; the box ref showed `Event 5 of 20`) and Live (`sleep 2` record vs `--wait 4500`; the box ref showed `Event 20 of 21`) both passed on the box in headless Chrome. They are journeys (R21), not hard gates, so a slow VM costs at most a re-seeded retry.
13. **Real logs, approximated clocks (accepted, disclosed).** The P3/P4 fixture timestamps come from the edges of the orchestrator's tool calls (provenance in `fixtures/replay/README.md`), not from a running `dd`. Every duration in the spec comes from the server's own `timeline()` over those logs (R18 parity), so the spec is self-consistent even if a minute is off from wall-clock reality. P3's `Intake 3h 32m` is real (the spec was written before the launch).
14. **Pick 4's last frame shows `Physical · not_verified` (accepted).** The physical's re-check after the W19 ruling was a reply on the same agent, which `dd` cannot express as a second run. The frame is faithful to the log, and the frame-19 caption reads `The verdict was VERIFIED.` The demo voice-over should say "re-checked". Teaching `dd` a re-check event is a later pick, not this one.
15. **Fixture text mentions KPD (accepted, disclosed).** The real scouting reports in logs 93/94/98/99 quote the repo's own FORBIDDEN guard sentence ("Nothing KPD, kpdlawgroup, or debt-collection related…"). That is the same text already in the repo's docs, not KPD content. No fixture contains anything else KPD-related.
